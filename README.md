# pi-extension-manager

一个中文 Pi 扩展管理器。在全屏 TUI 中按作者与来源浏览扩展，查看中文功能简介，管理单项和整包开关，核对暂存改动，以及更新、卸载已有包。

基于 `@earendil-works/pi-coding-agent`，已在 Windows、Node.js 24、Pi 1.5.0 下验证。

## 安装

```sh
pi install git:github.com/rhine9473/pi-extension-manager
```

安装后在 Pi 中运行 `/reload`，再输入 `/extension-manager`。包声明只加载 `index.ts`，辅助模块和测试文件不会被当成独立扩展加载。

如果已经把旧副本放在 `~/.pi/agent/extensions/extension-manager/`，迁移到 Git 安装前请先移走旧副本，避免同时加载两个同名命令。当前本地副本也可以继续单独使用；整个目录就是一份完整扩展。

更新 Git 安装的版本：

```sh
pi update --extension git:github.com/rhine9473/pi-extension-manager
```

入口：`index.ts`，命令：`/extension-manager`。
整个 `extensions/extension-manager/` 目录是一份完整扩展，界面组件、核心逻辑和说明都在其中。Pi 自动发现 `index.ts`；其他模块只由入口导入。同步本地扩展时保留整个目录。
运行模块使用 `.ts` 格式，确保 Pi 同一进程中 `/reload` 能读取更新后的辅助函数和功能说明；测试文件使用 `.test.mjs`。

## 打开

1. 在 Pi 当前会话运行 `/reload`，或重新启动 Pi。
2. 输入 `/extension-manager`。
3. 进入扩展总览：宽终端左侧为列表、右侧为选中项详情，窄终端自动收紧布局。列表按作者 / 来源分区，同一作者的扩展集中显示；方向键只选择扩展项，跳过区块标题。Tab 切换「扩展 / 包」。扩展详情直接显示在右侧，Space 暂存启禁；包页 Enter 打开包菜单。

管理器以全屏覆盖层显示，主列表、菜单和确认页均遮住背景会话；退出后恢复原会话。首页使用管理器专用的 `ManagerDashboard`，跟随 Pi 当前主题，不修改全局界面。普通操作菜单使用本地 `WrappingSelector`；确认和详细预览使用 `ReviewSelector`，说明区滚动时操作按钮保持可见。

这是 Pi 内部的中文终端交互面板（TUI），不是独立桌面窗口。
无需 API 调用即可管理；浏览清单不调用模型，不联网、不执行被查看扩展。

## 快捷键

底部按当前页面、选中项和未保存状态显示可用操作。只读扩展不提示启停，更新 / 卸载只出现在可操作的包上，保存 / 差异 / 放弃只在有未保存改动时显示。搜索时底部切换为搜索操作提示。

| 按键 | 操作 |
|---|---|
| ↑ / ↓ | 循环选择扩展或包 |
| Tab | 切换扩展 / 包列表 |
| / | 面板内搜索名称、作者、所属包、路径、来源和功能说明，输入时实时筛选；Enter 或 Esc 结束输入并保留关键词，`Ctrl+U` 清空 |
| Space | 暂存当前项的启禁：底部会写明「空格 禁用」或「空格 启用」；包页为「整包关闭 / 开启」。不可操作时不会静默，会说明原因（自身受保护 / 整包已关闭 / 项目作用域 / 包目录缺失） |
| Enter（包页） | 打开包菜单；扩展页不再弹出重复的详情菜单 |
| s / p / x | 保存 / 查看暂存差异 / 放弃暂存。保存确认页与 `p` 页共用同一份改动清单 |
| u / d | 更新 / 卸载选中包；执行前仍需确认。不允许时同样说明原因，而不是按键无反应 |
| Esc | 逐级返回：搜索框内 → 结束输入保留筛选；有筛选 → 清除筛选回到完整列表；列表无筛选 → 退出管理器（有未保存改动时先问如何处理） |
| PageUp / PageDown | 滚动主界面详情或确认页说明，不改变选中的扩展 |
| Ctrl+↑↓、鼠标滚轮 | 在确认或预览页翻阅说明；↑↓ 选择底部操作 |

搜索、标签页和选中项在保存、启禁等操作后保留。终端调整大小后重新计算布局。列表显示的是配置状态，实际加载结果以 Pi 启动或 `/reload` 报告为准。
## 功能

- 由 Pi 的 `DefaultPackageManager.resolve` 枚举配置资源：本地自动发现、settings 声明、本地/npm/git 包子扩展、四个内置扩展。
- 按作者 / 来源集中显示，分组标题标注数量；滚动时保留分组提示。优先读取包的 author，缺失时使用仓库归属或 npm 范围；无作者信息的本地扩展单独归类，Pi 内置扩展另列。作者未知时不会从文件名猜测。
- 浏览、分页、搜索名称、作者、所属包、路径、来源和功能说明。通用 `dist/index.ts` 入口显示所属包名。
- 右侧集中显示功能说明、路径、来源、作用域、版本和配置状态，不再提供重复的扩展详情弹窗；内容放不下时以 PageUp / PageDown 滚动，也可按功能文字搜索。
- 包菜单中选择子扩展会回到主列表并定位该扩展，可直接查看右侧详情或按 Space 暂存启禁。
- 功能简介按上游原意翻译成中文，保留 Agent、Code Mode、MCP、TUI、Git、npm 等术语和真实命令名。内置、本地（含 `magpie.ts`）、OpenPI 与其子扩展、pi-sync 包均提供中文简介；描述产品能力，不把本机开关状态写成产品限制。未收录翻译的英文文档会标注「原文未翻译：…」。
- 新增扩展在重开面板后自动发现。当前内置、本地（含 `magpie.ts`）、OpenPI 及 pi-sync 提供已核对的中文简介；其他扩展读取自身的 package.json 描述、README 或文件开头说明注释，缺少说明时明确标注。简介只读文档，不执行扩展代码。
- 右侧状态行不再重复（旧版显示「已启用 · 启用 · Git」），列表也不会把同名包再写一遍；作用域与文件状态合并为一行，路径单独成行并把 agent 目录缩写成 `~`（如 `~/extensions/smart-models.ts`），避免 `：C:\…` 孤悬行首；内置扩展不显示路径行。常见扩展在 24 行终端单屏显示完整。
- 单项启用/禁用只暂存官方 `+path` / `-path` 规则。包规则保留 skills/prompts/themes 等其他字段。
- 规则里的 `\` 一律按路径分隔符理解：Windows 写的 `+extensions\x.ts` 在 macOS/Linux 也能匹配同一路径，重新保存后统一写成 `/`，不会残留清不掉的旧规则。
- 包页支持 Space 或 Enter 菜单切换整包：同时关闭扩展、技能、提示词和主题，保留文件；开启时恢复原来的单项规则。关闭期间子扩展显示 `[包已关]` 并且不可单独启停。
- 来源标签只有一套说法，列表、详情和提示一致：`自动发现`（extensions 目录里的文件）、`配置声明`（settings 里点名的文件）、`本地包`、`Git 包`、`npm 包`、`Pi 内置`。内置项显示 `mcp`、`codemode`，不再露出 `builtin:mcp` 这种原始 ID；`auto` / `builtin` 这类没有地址的来源不再重复贴一遍。
- 版本号只在包的 manifest 真的声明时才显示（`版本：1.1.0`）。本地散文件、目录扩展和内置扩展**不再出现版本行**，也不写「未知」；不声明版本的包会改说「该包不声明版本号；更新结果按安装文件时间判断」。更新确认页显示「当前版本」，更新完成时给出「版本 1.1.0 → 1.2.0」「版本仍为 1.1.0，但安装文件已改写」或「版本与安装文件均未变化（…已是最新或来源固定了版本/ref）」；没有版本号可比的包改用「该包不声明版本，但安装文件已改写 / 安装文件也没有变化」。判断依据是安装目录 package.json 的版本与修改时间，不额外调用 git/npm，也不联网。
- 包列表区分已开启、部分启用、已关闭与缺失。整包关闭的子扩展标为 `[包已关]`，与管理器自身的 `[只读]` 分开。整包开关同样需要按 `s` 保存并 reload 才实际生效。
- 关闭时用 Pi 官方四类空资源过滤器生效，并把恢复信息一并放在 `settings.json` 的包声明内；更新包会保留这些规则，也可随 pi-sync 同步。
- 修改后再次用官方解析器核验：目标状态正确且其他资源状态不变，否则拒绝修改。
- 保存、更新和卸载在同一页展示说明与确认 / 取消，不再先进入只有“返回”的预览页。长说明可滚动，短说明一次展示完成。
- `p` 差异页和保存确认页显示人话清单（如「禁用 bash-timeout · openpi」「关闭整包 openpi（文件保留，重开时恢复单项设置）」），不再贴整段 JSON。整包关闭会用一行概括其子扩展；若关闭前还暂存过子项改动，清单会额外注明「↳ 重开后恢复：禁用 x」，避免改动被整包行掩盖。
- 保存前确认，检查配置是否被外部操作更改，备份原始字节，再以同目录临时文件替换并回读核验。
- 包管理支持单包更新和卸载；执行前确认并备份。新增来源使用 Pi 官方 `pi install`。
- 包操作通过当前 Pi 的 CLI 入口、独立 argv 数组和管道输出执行，不拼接 shell、不另开 TUI；失败时显示错误摘要。
- 更新固定版本/ref 不会擅自改成最新版。
- 本地包卸载只移除声明，不删除原目录；npm/git 受管安装可能被移除。
- 管理器自身及包含自身的包受保护。
- 任何被拒绝的按键都会给出一条中文原因（`ctx.ui.notify` 警示），不会出现「按了没反应」；空列表和搜不到时也会写明当前的关键词与清除方式。
- 退出时可立即 reload，或稍后手动 `/reload`。

## 作用域和限制

- 固定管理全局扩展和包；不读取或修改项目 `.pi/settings.json`。项目扩展需要管理时使用 Pi 官方 `pi config --local`。
- 不提供范围切换、手动刷新、日志页面或分类筛选；通过搜索定位扩展，重开面板读取外部变化。
- 显示的是 **配置状态**，不是当前进程实际加载成功状态。修改保存后需 reload；最终加载错误由 Pi 报告。
- 显式命令行 `-e`、临时包、SDK 注入不纳入 settings 管理清单。
- 全局包可在面板更新和卸载；新增包使用 Pi 官方 `pi install`，再重开面板自动发现。本地包修改源文件后 `/reload`。
- 缺包保留在包列表；官方解析器未枚举的缺失本地文件不会凭空添加成可启用扩展。
- 不提供全盘删除、批量卸载或任意 shell 执行。本地源码绝不因为禁用而移动/删除。
- 备份及外部修改检查是恢复措施，不是安全沙箱；安装脚本或其他进程仍有用户权限。
- `settings` 备份不包含整个 npm/git 安装目录，不能撤销安装脚本副作用。

## 备份

目录：`<agentDir>/state/extension-manager/backups/`。运行时备份与扩展代码分开保存，不需要随扩展源码同步。
每个 JSON 备份记录 `originalFile`、`existed` 和 `originalText`。
恢复前退出 Pi，并确认当前配置没有其他需要保留的新修改。
若 `existed:true`，把 `originalText` 原样写回 `originalFile`；若 `existed:false`，备份表示原文件不存在。

## 验证

在仓库目录运行：

```sh
npm test
```

测试需要本机已经安装 Pi。Windows 默认查找全局 npm 安装的 `@earendil-works/pi-coding-agent`；其他安装位置通过环境变量 `PI_TEST_HOST` 指向该包的绝对目录（其中应含 `dist/`、`package.json` 和依赖）。其他操作系统的测试环境尚未完整验证。

测试在临时目录执行，不修改真实配置，不联网。
测试覆盖响应式布局、中文宽度、搜索与焦点、键盘导航、本地/包/内置发现、过滤器、包空数组启用后的兄弟状态、管理器及 symlink 自身保护、配置冲突、备份字节、实际 Pi TS 加载器、快捷键启禁保存/reload、本地包卸载、未信任项目和 RPC 模式拒绝。

目录只包含入口、运行模块和测试；清单快照与早期设计稿已删除，面板每次打开都会重新发现当前资源。
