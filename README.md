# pi-extension-manager

在 Pi 中按作者与来源浏览扩展，用全屏中文 TUI 管理单项开关、整包开关、暂存改动，以及包的更新和卸载。

基于 `@earendil-works/pi-coding-agent`，需要 Node.js **22.19.0 或更新版本**。已在 Windows、Node.js 24、Pi 1.5.0 下验证，其他操作系统尚未完整验证。源码与测试均为 TypeScript。

## 安装与更新

```sh
pi install git:github.com/rhine9473/pi-extension-manager
```

安装后在 Pi 中执行 `/reload`，再输入 `/extension-manager`。

管理器会保护自身及包含自身的包。更新本扩展请在终端执行：

```sh
pi update git:github.com/rhine9473/pi-extension-manager
```

更新后重新启动 Pi，或执行 `/reload`。

也可以将整个仓库目录放在 `~/.pi/agent/extensions/extension-manager/` 使用。包入口是 `index.ts`，辅助模块和 `*.test.ts` 不会被当作独立扩展加载。

从本地副本迁移到 Git 安装时，先将旧目录移出自动发现目录；如果曾在 `settings.json` 的 `extensions` 或 `packages` 中显式声明旧副本，也需移除对应的旧路径，避免重复加载。

## 使用

1. 用 `↑↓` 选择扩展；右侧显示功能简介、来源和配置状态。
2. 按空格暂存启用或禁用，按 `p` 查看改动，按 `s` 确认保存。
3. 保存后退出面板，可选择立即 reload，或稍后手动执行 `/reload`。

| 按键 | 操作 |
|---|---|
| `↑` / `↓` | 循环选择扩展或包，跳过分组标题 |
| `Tab` | 切换扩展页与包页 |
| `/` | 搜索名称、作者、所属包、路径、来源或功能说明；输入时实时筛选 |
| `Enter` / `Esc`（搜索框内） | 结束输入，保留筛选；`Ctrl+U` 删除光标前内容 |
| `Space` | 暂存单项开关；包页暂存整包开关，底部显示具体动作 |
| `Enter`（包页） | 打开包菜单，查看详情或浏览子扩展 |
| `s` / `p` / `x` | 保存 / 查看暂存差异 / 放弃暂存改动 |
| `u` / `d`（包页） | 更新 / 卸载选中包，执行前需要确认 |
| `Esc`（有筛选） | 清除筛选，回到完整列表 |
| `Esc`（无筛选） | 退出管理器；有未保存改动时先选择处理方式 |
| `PageUp` / `PageDown` | 滚动主界面详情或确认页说明 |
| `Ctrl+↑↓`、鼠标滚轮 | 在确认或预览页滚动说明 |

在受保护项或 `[包已关]` 子扩展上按空格，以及尝试更新本地包等不可操作情形，会提示原因。没有选中项或按了未绑定的键时不触发操作。

## 行为与限制

- **仅管理全局配置。** 不读取或修改项目 `.pi/settings.json`；项目资源使用 Pi 的 `pi config --local` 管理。
- **按作者与来源分组。** 优先读取包的作者信息，缺失时使用仓库归属、npm 范围等信息；没有作者信息的本地扩展单独归类，Pi 内置扩展另列。
- **中文功能简介。** 已收录的内置扩展、本地扩展及 OpenPI、pi-sync 提供中文说明，保留 Agent、Code Mode、MCP、TUI 等术语。其余扩展读取自己的 `package.json`、README 或文件头部注释；英文原文标为“原文未翻译”，没有说明时明确标注。浏览清单不执行被查看的扩展代码，也不调用模型。
- **单项与整包开关。** 单项使用 Pi 的启禁规则；整包开关同时作用于扩展、Skills、Prompts 和 Themes。关闭整包保留文件与原单项设置，重新开启时恢复；关闭期间子扩展标为 `[包已关]`，不能单独启停。
- **暂存后保存。** `p` 页和保存确认页共用改动摘要。整包开关会概括其子项；关闭前暂存的子项规则变化也会注明，方便核对重新开启后的设置。
- **配置状态不等于加载结果。** 启禁、保存和包更新后，需要 reload 才尝试生效，实际加载错误以 Pi 的报告为准。重新打开管理器会重新发现资源。
- **包更新与卸载。** 交给当前 Pi 的 CLI 执行。固定 npm 版本或 Git ref 不会自动改为最新版；本地包修改源文件后 reload。本地包卸载只移除声明，受管 npm/Git 安装目录可能被删除。新增包使用 `pi install`。
- **版本与更新证据。** 扩展页仅在所属包声明 `version` 时显示版本号；本地散文件、目录扩展和内置扩展不虚构版本号，包页会说明未声明版本的情况。更新提示对比的是包根目录 **`package.json` 的版本号与修改时间**，只作轻量参考：Git 更新可能只改变源码而不改该文件，因此版本或时间未变不能证明代码没有更新。
- **跨设备路径。** 切换单项时，可识别该项已有的反斜杠相对路径 `+`/`-` 规则，新写入的 `+`/`-` 规则使用 `/`；不会批量转换其他规则。若扩展经目录或 glob 声明引入，管理器可能补写该文件的绝对路径，跨设备同步前请检查；Windows 盘符绝对路径通常不能直接迁移到其他系统。
- **范围边界。** 显式命令行 `-e`、临时包、SDK 注入不纳入全局配置管理。缺失包保留在包页；不提供全盘删除、批量卸载或任意 Shell 执行入口。

## 配置备份

保存配置和执行包操作前，会备份原始全局 `settings.json`。保存时检查它是否被外部修改，并回读核验写入结果。

备份目录为 `<agentDir>/state/extension-manager/backups/`，与扩展源码分开。每份备份记录 `originalFile`、`existed` 和 `originalText`。

恢复前退出 Pi，核对目标文件与备份内容：`existed: true` 时将 `originalText` 写回 `originalFile`；`existed: false` 表示原文件当时不存在。配置备份不包含 npm/Git 安装目录，不能撤销安装脚本或包文件变化。

## 本地测试

运行测试需要 Node.js **≥22.19.0**，并已安装 Pi。在仓库目录执行：

```sh
npm test
```

Windows 默认从 `%APPDATA%/npm/node_modules/@earendil-works/pi-coding-agent` 加载 Pi。**非 Windows 环境或自定义安装位置必须设置 `PI_TEST_HOST`**，指向包含 `package.json`、`dist/` 和依赖的 Pi 包目录，例如：

```sh
PI_TEST_HOST=/absolute/path/to/@earendil-works/pi-coding-agent npm test
```

测试在临时目录执行，不修改真实配置、不联网；覆盖启禁与整包恢复、配置保存与冲突、搜索交互、响应式布局和实际 Pi 扩展加载器。
